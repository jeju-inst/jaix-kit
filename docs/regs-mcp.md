## 1. 목표와 범위

- 연구원이 Claude(Desktop Cowork·Code 탭·웹·Claude Code)와 ChatGPT·Codex에서 **"출장 숙박비 상한은?"** 같은 규정 질문을 하면, 조문 번호와 원문 근거를 붙여 답하게 한다(인수 시험 6-3).
- 원문(`jeju-inst/ji-regulations`, private)을 연구원 PC에 내려보내지 않는다. 서버가 검색 결과만 돌려준다.
- **서버는 검색만 하고 답을 쓰지 않는다.** 답은 연구원 좌석의 모델이 검색 결과를 인용해 쓴다. 그래서 서버에 LLM 비용이 들지 않고, 서버가 지어낸 답을 내놓을 일도 없다.
- 읽기 전용이다. 쓰기 도구는 없다.

ChatGPT 채팅 ────────────┤  OpenAI 클라우드가 호출
Codex CLI·앱 ────────────┤  연구원 PC가 직접 호출

   ├ 색인: ~/.local/share/jaix-regs/index/<ji-regulations 커밋>/

   └ 원문 스냅샷: ji-regulations의 공개본 내보내기(public-export.json 허용 목록) 결과

## 3. 호스팅

### 3.1 studio에서 돌린다

- 이미 상시 가동 중이고, `jaix.namun.net`(gw 배포)·`spacemath.namun.net`·`hwp.namun.net`이 같은 방식(127.0.0.1 바인드 + cloudflared)으로 떠 있다. 운영 방식을 새로 만들 필요가 없다.
- 임베딩(bge-m3)을 이미 Ollama로 studio에서 돌린다(`llm-playground/pilots/doc-rag`). 검색 시 질문 하나를 임베딩하는 비용만 든다.
- **단일 장비 위험**: studio가 멈추면 규정 Q&A도 멈춘다(2026-08-14 하드 프리징 이력). 1차는 감수하고, 외부 가동 감시(5분 간격 `GET /health`)로 알아채게 한다. 다른 업무에 영향은 없다.

### 3.2 `jaix.namun.net`을 재사용하지 않는다 (Q1)

`jaix.namun.net`은 **기관 공인 IP만 통과**시키는 구조다(Cloudflare Access Bypass by IP + 서버 IP 게이트, ji-gw-ai `docs/share-deploy.md`). 규정 MCP는 이 구조와 맞지 않는다.

- Claude 커스텀 커넥터의 MCP 호출은 연구원 PC가 아니라 **Anthropic 클라우드에서** 온다. ChatGPT도 OpenAI 클라우드에서 온다. 출발 IP가 기관 IP가 아니므로 IP 게이트에 모두 막힌다.
- 같은 호스트에 "이 경로만 IP 게이트 예외"를 두면 Access 정책 하나에 두 가지 보호 모델이 섞인다. 정책을 고치다 gw wheel 경로까지 열릴 위험이 생긴다.
- 그래서 **호스트를 분리**한다. 터널은 기존 `jaix` 터널을 재사용하고 ingress 규칙만 하나 추가한다(`hostname: <규정 호스트>`, `service: http://127.0.0.1:8791`). 이 호스트에는 **Cloudflare Access 애플리케이션을 두지 않는다.** Access 로그인 화면이 앞에 서면 커넥터의 서버 간 호출이 실패한다. 보호는 4절의 OAuth가 맡는다.
- 도메인: 지금 쓰는 `namun.net`은 개인 도메인이다. 기관 도메인(`ji.re.kr` 하위)으로 옮기려면 기관 DNS 담당 부서와 협의해야 한다. 1차는 `namun.net`으로 하고, 옮길 때는 커넥터 URL만 바꾸면 된다(연구원은 커넥터를 다시 연결해야 함).

### 3.3 코드와 실행 위치 (Q6)

- 코드: 새 private 저장소 `jeju-inst/ji-regs-mcp`. 원문·색인·비밀은 넣지 않는다. 검색 코드는 `doc-rag`(청커·색인·평가 셋)를 옮겨 온다.
- 실행: gw 배포처럼 운영 실행 트리(origin/main 고정)에서 launchd `com.namun.jaix-regs`로 돈다. 개발 체크아웃을 직접 실행하지 않는다.
- 비밀(IdP Client Secret, 토큰 서명 키)은 studio 로컬 `~/.config/ji-regs-mcp/secrets.toml`(권한 600)에만 둔다.

## 4. 인증

### 4.1 방식 비교

| 안 | 내용 | 판정 |
|---|---|---|
| **A. OAuth 2.1 (권고)** | 서버가 인가 서버를 겸한다. 인가 코드 + PKCE(S256), 동적 클라이언트 등록(RFC 7591), 공개 클라이언트. 로그인 자체는 기관 IdP로 넘긴다. **spacemath(`spacemath.namun.net`)에서 같은 구조로 claude.ai 웹 커넥터·Claude Code·Codex 연결을 이미 확인했다**(space-math `docs/개발/AI-연결-MCP.md`, 2026-10-27) | 연구원마다 자기 계정으로 연결하고, 퇴직하면 IdP에서 막힌다 |
| B. 경로 토큰(인증 없음) | URL에 긴 무작위 토큰을 넣고 커넥터 인증을 끈다(msg.namun.net 방식) | URL 하나가 새면 누구나 읽는다. 조직 전원이 같은 URL을 쓰므로 회수도 어렵다. 쓰지 않는다 |
| C. Cloudflare Access 로그인 | 호스트 앞에 Access 로그인을 둔다 | 커넥터는 서버 간 호출이라 Access 대화형 로그인을 통과하지 못한다. 쓰지 않는다 |

### 4.2 기관 IdP (Q2)

로그인 확인을 서버가 직접 하지 않고 기관 계정 시스템에 맡긴다. 서버는 IdP가 돌려준 신원에서 아래만 확인한다.

- 이메일 도메인이 `ji.re.kr`인가.
- 계정이 정지·삭제 상태가 아닌가.

| | NAVER WORKS (권고) | Google Workspace |
|---|---|---|
| 전 직원 계정 | **있음**(웍스 `/users` 전수 조회로 확인, ji-worksmobile-admin) | 확인 못 함 |
| 필요한 것 | Developer Console 앱 1개(로그인 전용, 본인 정보 읽기 스코프만), Redirect URL `https://<규정 호스트>/oauth/idp/callback` | Google Cloud OAuth 클라이언트(사용자 유형 "내부") |
| 비고 | 웍스 nworks 앱(`docs/works.md`)과는 **다른 앱**으로 만든다. 한쪽 비밀을 바꿀 때 다른 쪽이 흔들리지 않게 하기 위해서다 | |

본인 정보 조회에 필요한 웍스 스코프 이름은 구현 때 콘솔에서 확인한다(미확인).

### 4.3 토큰

- 접근 토큰 1시간, 갱신 토큰 30일. 갱신할 때마다 IdP에서 계정 상태를 다시 확인한다. 퇴직자는 최대 1시간 안에 끊긴다.
- 토큰 서명 키는 studio 로컬에만 있다. 키를 바꾸면 전원이 다시 연결해야 한다.
- 돌아갈 주소(redirect URI)는 허용 목록으로 제한한다: Claude 콜백(`claude.ai`, `claude.com`), ChatGPT 콜백, 로컬 loopback(Codex·Claude Code용, 포트 무관). spacemath의 허용 규칙을 그대로 쓴다.

### 4.4 호스트별로 붙는 방식

| 호스트 | 붙는 방식 | 연구원이 할 일 | 상태 |
|---|---|---|---|
| Claude (Desktop Cowork·Code 탭·웹·모바일) | 관리자가 **조직 커스텀 커넥터**로 한 번 등록 | 커넥터 화면에서 "연결" → 웍스 로그인·허락 1회 | 웹 커넥터 + DCR은 spacemath로 확인. **조직 단위 등록은 11/1 이후 실측** |
| Claude Code CLI | 같은 claude.ai 계정이면 조직 커넥터가 자동으로 보임 | 없음(첫 사용 때 연결이 안 됐으면 `/mcp`에서 인증) | spacemath로 확인 |
| ChatGPT 채팅 | 워크스페이스 관리자가 커스텀 커넥터(MCP)로 등록 | 첫 사용 때 로그인·허락 1회 | **미확인.** 워크스페이스 플랜에서 커스텀 MCP 커넥터 허용 여부·콜백 주소를 11/1 이후 확인 |
| Codex (CLI·앱) | `codex mcp add jaix-regs --url https://<규정 호스트>/mcp` → OAuth 자동 감지 | 브라우저 허락 1회. `jaix setup`이 등록 명령을 대신 실행한다 | spacemath로 등록·토큰 발급까지 확인(도구 호출은 미확인) |
| Hermes + 슬랙 | Hermes가 원격 MCP(HTTP+OAuth)를 붙일 수 있는지 미확인 | — | 1차 범위 밖, 확인 후 결정 |

- **ChatGPT 호환을 위해 도구 이름에 `search`·`fetch`를 쓴다.** ChatGPT의 지식 검색형 커넥터가 이 두 이름을 기대한다(구현 때 현재 요구 사항을 다시 확인한다).

## 5. 검색 방식

### 5.1 지금까지의 근거

| 방식 | 근거 | 판단 |
|---|---|---|
| R: 조문 단위 RAG(`doc-rag`, bge-m3) | 실제 업무 질문 41건에서 hit@5 89%, MRR 0.732, 담당자 질문 6/6 | 1차 검색 엔진으로 쓴다 |
| W: LLM 위키(`ji-regs-annotations`) | 블라인드 A/B 위키 없음 2/6 → 있음 6/6. 다만 **위키를 쓴 사람이 고른 문항**이라 일반화할 수 없다. regs3 3방식 비교는 채점 1문항뿐이다 | 1차에서 뺀다(Q4) |
| N: NotebookLM | regs3 1문항에서 지어낸 조문(💀) 1건 | 해당 없음(외부 제품) |

- 위키는 공포된 원문이 아니라 해석·공백·구어 대응을 적은 주석이다. 서버가 그것을 근거처럼 돌려주면, 모델이 해석을 조문처럼 인용할 위험이 있다.
- 재판단 조건: regs3 채점 문항이 20건 이상 쌓이고, W가 R보다 낫다는 결과가 나오면 2차에 `notes` 필드("해석 주석, 공식 규정 아님" 표시)로 붙인다.

### 5.2 도구 (4개, 전부 읽기 전용)

| 도구 | 입력 | 돌려주는 것 |
|---|---|---|
| `search` | `query`, `k`(기본 5, 최대 8) | 조문 후보 목록: `id`, 규정명, 조·항 번호, 조 제목, 발췌(400자 이내), 시행일 |
| `fetch` | `id` | 조문 전문, 관련 별표, 원문 판본(`ji-regulations` 커밋) |
| `who_handles` | `task` | 공개용 사무분장에서 담당 부서·담당 업무 후보 |
| `find_form` | `situation` | 상황별 서식과 역할 기반 결재선 |

- 검색은 **벡터 + 키워드 혼합**이다. 조문 번호("제12조")·고유 용어("일비")는 키워드가, 구어 질문("출장 가서 밥값")은 벡터가 잡는다.
- Ollama가 죽으면 키워드 검색만으로 답하고 결과에 `engine=keyword`를 표시한다(TS-RUNTIME-3).
- MCP 서버 안내문(instructions)에 답변 규칙을 넣는다: 조문 번호를 인용한다. 검색 결과에 없으면 "규정에서 찾지 못함"이라고 답한다. 추측으로 조문을 만들지 않는다.

### 5.3 사용량 예산

- 원격 커넥터의 도구 스키마도 매 대화에 실린다. 도구 4개, 설명은 한두 문장으로 써서 **상시 분량 800토큰 이하**를 목표로 한다(TS-TOKEN-1 3k의 일부).
- `search` 결과는 발췌만 돌려준다. 한 번 호출에 **3k토큰 이하**로 하고, 전문은 `fetch`로 필요한 조문만 읽게 한다.
- 구현 PR에 TS-TOKEN-3 방법으로 잰 값을 적는다.

## 6. 노출 범위

### 6.1 경계는 이미 있는 공개본 허용 목록 하나로 한다

`ji-regulations`에는 이미 **공개본 내보내기**가 있다(`public-export.json` 허용 목록 + `scripts/export_public_snapshot.py`, 누출·참조 무결성 검사 포함). 서버는 원본 저장소를 직접 색인하지 않고, **이 내보내기 결과만 색인**한다. 노출 경계가 저장소 안 한 곳에만 있게 하려는 것이다(TS-SECRET-3 allow-list).

| 넣음 (공개본 허용 목록) | 뺌 |
|---|---|
| 공식 규정 Markdown(`rules/docs/`, 규정집 전문 정제본) | 연구과제 아카이브(`project-archives/`), 수집 스크립트 |
| 공개용 사무분장(전화번호·내부 Slack 출처·휴직 정보 제거) | 원본 HWP/PDF(`source/`), 내부 드라이브 색인 |
| 상황별 서식 매핑, 역할 기반 결재선(실명 결재선 아님) | Slack에서 모은 인사발령 타임라인(`doc-rag`의 `personnel-changes.md`) |
| 정원표(`capacity.yaml`) | 위키 주석층, regs3 채점 기록 |

- 이 공개본은 원래 공개 저장소(NotebookLM 소스)를 염두에 두고 정제한 것이다. 인증 뒤에서만 보여 주므로 위험은 그보다 낮다.
- **공개용 사무분장에 담당자 이름이 남는다**(전화번호는 빠짐). 원내 인증 뒤에서만 보이므로 허용하자고 제안한다. 이름도 빼야 하면 공개본 변환 규칙(`public_assignments`)을 고친다. 그러면 공개본 쪽도 같이 바뀐다.

### 6.2 판본 갱신

- launchd가 1시간마다 `ji-regulations` main을 확인한다. 새 커밋이 있으면 공개본 내보내기(검사 포함) → 새 색인 → 원자적 교체 순서로 진행한다. 검사가 실패하면 이전 색인을 그대로 쓴다.
- 모든 응답에 `corpus_commit`과 조문 시행일을 붙인다. "언제 판본 기준인지"를 답에서 확인할 수 있게 하기 위해서다.

### 6.3 기록 (Q5)

- 남기는 것: 시각, 사용자 식별자(IdP 사용자 ID), 도구 이름, 결과 건수, 소요 시간.
- 남기지 않는 것: **질문 원문.** 징계·휴직·육아 같은 개인 사정이 질문에 드러날 수 있다.
- 보존 90일. studio 로컬에만 둔다.

## 8. 11/2 관리자 콘솔 설정 때 필요한 값

11/2에 아래 값을 확인한다. **실제 등록은 서버가 OAuth까지 뜬 뒤에 한다**(Q3). 등록하는 순간 연구원 화면에 커넥터가 보이므로, 연결이 실패하는 커넥터를 먼저 내보내지 않기 위해서다.

### Claude 조직 (Team 관리자 콘솔 → 커넥터)

| 항목 | 값 |
|---|---|
| 커넥터 이름 | `제주연구원 규정 Q&A` |
| 원격 MCP 서버 URL | `https://<규정 호스트>/mcp` (Q1) |
| 인증 | OAuth. 동적 클라이언트 등록을 쓰므로 고급 설정의 Client ID/Secret은 **비워 둔다** |
| 콜백 주소 | 서버 쪽 허용 목록에 `https://claude.ai/api/mcp/auth_callback`(및 `claude.com` 짝)이 있는지 확인. 콘솔에 입력하는 값은 아님 |
| 사용 범위 | 조직 전원 |
| 도구 권한 | 4개 모두 읽기 전용 → "항상 허용" 권장(매번 승인 창을 띄우지 않게) |

### ChatGPT 워크스페이스 (확인 항목)

- 워크스페이스 플랜에서 관리자가 커스텀 MCP 커넥터를 추가할 수 있는가, 개발자 모드가 필요한가.
- 콜백 주소 값(서버 허용 목록에 넣을 값).
- 동적 클라이언트 등록을 지원하는가. 지원하지 않으면 서버에서 ChatGPT용 클라이언트를 미리 발급해 콘솔에 넣는다.

### IdP (Q2 = 웍스일 때, 웍스 관리자 작업)

- Developer Console → Client App 새로 만들기: 이름 `JAIX 규정 Q&A 로그인`.
- Redirect URL `https://<규정 호스트>/oauth/idp/callback` 입력 후 **추가 버튼까지 누른다**(2026-08-24, 입력만 하고 추가를 누르지 않아 로그인이 실패한 이력).
- 스코프는 본인 정보 읽기 하나만. 서비스 계정 위임은 켜지 않는다.
- 앱 관리 권한(앱 접근)은 "제한, 관리자 본인만"으로 둔다.
- Client ID/Secret은 studio `~/.config/ji-regs-mcp/secrets.toml`에만 기록한다. 저장소·메신저에 붙이지 않는다.

### Cloudflare

- `cloudflared tunnel route dns jaix <규정 호스트>` (DNS 레코드 추가).
- 이 호스트에는 **Access 애플리케이션을 만들지 않는다**(3.2).

## 10. 도구 편입 표준과의 관계

규정 Q&A는 플러그인이 아니라 **원격 커넥터**다. 그래서 FORMAT·VER·LOCK·MCP-1·WIN·INSTALLER 규칙은 해당 없다. 적용하는 규칙은 다음과 같다.

| 규칙 | 적용 |
|---|---|
| TS-TOKEN-1·2·3 | 도구 스키마 상시 분량과 `search` 1회 분량을 측정해 구현 PR에 적는다 |
| TS-SECRET-1·3 | 비밀은 studio 로컬에만 둔다. 노출 범위는 공개본 허용 목록(allow-list)으로 정한다 |
| TS-RUNTIME-3 | 임베딩이 안 되면 키워드 검색으로 넘어가고 결과에 표시한다 |
| TS-ACCEPT-1 | 인수 시험 6-3 |
| TS-STEPS-1 | 연구원이 할 일: 첫 사용 때 커넥터 "연결" → 웍스 로그인·허락 1회 |
| TS-CHANNEL-1 | 4.4 표. DC·DK·CC는 조직 커넥터, CX는 jaix 등록, HS는 미확인 |

표준에 "원격 커넥터" 절이 없다. 구현 PR이 머지되면 `docs/tool-standard.md`에 CONNECTOR 절(호스트 분리, OAuth, 노출 범위 allow-list, 기록 범위)을 추가하는 PR을 따로 올린다.
