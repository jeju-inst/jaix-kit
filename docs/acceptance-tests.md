# JAIX 실업무 인수 시험 목록

11/10 전원 배포 전에 **"실제 업무에서 끝까지 되는가"**를 확인하는 목록이다.
단위 테스트·CI가 통과해도 연구원 PC에서 실제 서식·실제 계정으로 안 되면 실패로 본다.

- **언제**: 11/1-11/9 (Team 관리자 콘솔이 열린 뒤). 관리자 콘솔이 필요 없는 항목은 그 전에 namun-ji `jaix-test` 계정에서 미리 시험함.
- **누가**: AI센터 파일럿 2-3명 + namun-ji 깨끗한 계정.
- **기록**: 항목마다 채널별로 ✅ 통과 / ⚠️ 우회로 됨 / ❌ 실패 / — 해당 없음, 그리고 **사용량(%)**을 적는다.
- **사용 데이터**: 개인정보가 없는 시험용 서식·문서를 `jaix-kit` 밖 공유드라이브 `시험자료/`에 둔다(저장소에 올리지 않음).

## 7. 사용량 한도 (Team 좌석 ≈ Pro의 1.25배)

연구원 대부분이 가장 작은 요금제를 쓴다. **도구가 맞게 동작해도 사용량 한도에 금방 걸리면 실업무에서는 실패다.**

| # | 시나리오 | 통과 기준 |
|---|---|---|
| 7-1 | 평소 하루 업무 묶음(1-2 + 2-1 + 3-3 + 5-1 + 5-2)을 한 번에 | 5시간 한도의 **50% 이하**. `/usage`(또는 설정 › 사용량)에서 전후 % 기록 |
| 7-2 | 큰 작업 1건(1-4 보고서 30쪽 넣기) | 한도 안에서 끝남. 넘을 것 같으면 도중에 나눠 하자고 먼저 안내 |
| 7-3 | 플러그인만 켜고 빈 대화 시작 | 항상 붙는 비용(always-on)이 잠금 목록 전체 합계 **3k 토큰 이하** |
| 7-4 | Hermes 봇에 짧은 질문 10회 | 한 번에 쓰는 양이 같은 질문을 Desktop에서 할 때의 1.5배 이하 |
| 7-6 | Desktop에서 Opus를 고른 채로 7-1 반복 | Sonnet 대비 소모 배수를 기록해 온보딩 안내 근거로 씀 (Team은 조직 기본 모델을 강제할 수 없음) |
| 7-5 | 한도에 걸렸을 때 | 사용자가 알아들을 안내(언제 풀리는지, 다른 채널/모델로 우회)가 나옴 |
