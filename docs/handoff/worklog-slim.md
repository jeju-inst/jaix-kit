# worklog-slim — calendar-worklog 스킬 분량 줄이기 (Claude)

공통 규칙: [README.md](README.md). 태스크 #8.

## 목표
`plugin/skills/calendar-worklog/SKILL.md`(현재 약 47KB, 약 21k 토큰)를 **호출 한 번에 10k 토큰 이하**로 줄인다. 연구원 좌석은 Pro의 약 1.25배라 worklog 한 번 부를 때마다 21k를 싣는 것은 한도 초과로 이어진다. **동작은 그대로** 둔다 — 지금 AI센터에서 매일 쓰는 도구다.

## 방법 (권장)
- **점진 공개**: SKILL.md에는 공통 규칙·워크플로 목록·각 워크플로로 가는 안내만 남기고, 워크플로별 상세(0 셋업 마법사, 근태 빠른 등록, 일자별 기록, 명시 일정, 주간 과제 보고, 월간 직원소통공감회의 등)를 `references/<워크플로>.md`로 옮긴다. 에이전트가 해당 워크플로에서만 읽게 한다. 참고 구현: hwp-agent `skills/hwp-agent/references/`.
- 중복·예시 과다·역사 서술(왜 이렇게 됐나)은 줄이거나 `docs/`로 뺀다. 판단 근거가 되는 규칙은 지우지 않는다.
- frontmatter `description`은 트리거 정확도가 떨어지지 않게 유지(항상 싣는 분량이므로 짧게).

## 측정
- 바꾸기 전·후 바이트 수와 토큰 수를 PR에 적는다. 토큰은 Anthropic `count_tokens` API(키가 있으면) 또는 `claude -p`로 같은 질문을 던져 사용량 차이를 보는 방식 중 가능한 것으로. 근사치면 근사라고 적는다.
- 워크플로별로 "SKILL.md + 해당 reference" 합계가 10k 이하인지 표로.

## 동작 보존 확인
- 저장소의 기존 테스트·검사 스크립트가 있으면 전부 통과.
- 대표 발화 5개("지참 0835", "어제 정리", "5월 30일 14시 회의 등록", "주간 과제 보고", "이번 달 직원소통공감회의 자료 정리")에 대해 바꾸기 전·후 스킬이 **같은 단계·같은 도구 호출 계획**을 내는지 dry-run 성격으로 비교(실제 캘린더에 쓰지 않음). 결과를 PR 본문에.
