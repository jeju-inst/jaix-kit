# gw-share — 그룹웨어 도구 공유 빌드 (Claude)

공통 규칙: [README.md](README.md). 태스크 #5 중 gw 부분.

## 목표
`ji-gw-ai`(private, `~/dev/ji-gw-ai`)에서 **관리자 경로를 코드 차원에서 뺀** 연구원용 공유 빌드를 만든다. 연구원이 자기 계정으로 회의실 예약·간단한 결재 준비·결재 문서 읽기를 할 수 있어야 한다. 2026-10-22 사용자 결정: "관리자 경로를 뺀 공유 빌드를 따로 공개"(사내 한정 라이선스).

## 두 단계로 진행 — 1단계에서 멈추고 보고
1. **설계 PR (먼저)**: `ji-gw-ai`에 `docs/share-build.md`를 PR로 올린다. 담을 것:
   - 명령·모듈 전수 분류표: 공유 빌드에 **넣음 / 뺌 / 바꿈**, 근거.
   - 빼야 하는 것: gw admin 경로, Slack 관리자 토큰, Anthropic 토큰 의존, works(웍스) 서비스 계정, 기타 관리자급 자격증명. 사용자 본인 GW 계정 외의 권한이 필요한 모든 기능.
   - 빼는 방식: 별도 패키지/저장소(예: `jeju-inst/ji-gw-share`)로 추출 vs 같은 저장소 빌드 플래그. **코드가 아예 들어 있지 않아야 한다**는 조건을 만족하는 쪽으로 추천.
   - 공개 범위와 라이선스: 라이선스상 원외 재배포 불가 → 저장소 공개 여부·접근 방식(조직 private + 연구원 읽기 권한? 사내 배포?)을 선택지로 제시. **이건 사용자 결정 사항이다.**
   - Windows 의존성: uv · playwright chromium(설치는 jaix-setup) · pymssql, 원내망 필요 여부, `osascript` 알림의 OS 분기, 맥 키체인 `security` 의존을 Windows 자격 증명 관리자로 추상화하는 방법.
   - 사용량 예산(항상 싣는 분량 3k, 호출당 10k)에 맞는 스킬 구성.
   → **설계 PR을 올리고 완료 보고를 한 뒤 멈춘다.** 조율 세션과 사용자가 결정한 뒤 2단계를 시작한다.
2. **구현 PR (승인 후)**: 설계대로 추출·플러그인화(`.claude-plugin/plugin.json`, 스킬, 필요하면 stdio MCP), Windows CI.

## 하지 말 것
- 관리자 자격증명·토큰·내부 서버 주소·직원 개인정보를 공개 가능성이 있는 곳에 커밋.
- 원본 체크아웃 `~/dev/ji-gw-ai` 브랜치 전환(스킬 `gw`가 심링크로 직접 실행 중).
- 실제 GW에 쓰기 동작(결재 상신·예약 확정) 시험. 읽기·초안까지만, 쓰기는 사용자 확인 후.

## 완료 기준 (1단계)
- 분류표가 빠짐없이 모든 명령을 다룬다(`gw --help` 전수 기준).
- 사용자 결정이 필요한 항목이 PR 본문 맨 위에 질문으로 정리돼 있다.
